# API 生成节点固定默认值设计

日期：2026-07-21

## 目标

让经典画布中每次新建的“API生成”节点都有稳定、清晰且适合日常使用的默认选项，避免默认值受平台数组顺序、旧画布迁移状态或其他节点设置影响。

## 采用方案

采用固定默认值方案。新建节点统一使用一套默认配置；节点创建后，用户对该节点所做的修改继续随画布保存。

未采用的方案：

- 记住上一次设置：操作更快，但容易把临时比例、批量数量或高成本选项带到后续节点。
- 按输入图片动态复制全部设置：适合特定工作流，但行为不透明，且没有输入图片时仍需另一套规则。

## 新建节点默认配置

- API 平台：优先选择已启用且已配置凭据的主平台；当前配置下优先 `65535`。若不可用，则按现有平台优选规则回退。
- 模型：优先选择当前平台的 `gpt-image-2`；若平台不提供该模型，则使用该平台现有的模型优选规则。
- 分辨率：`2K`。
- 比例：默认 `1:1`。当节点接入参考图片后，自动切换为跟随第一张参考图的比例。
- 质量：`Q high`，请求值为 `high`。
- 补满：关闭。
- 数量：`1`。
- 自定义比例、自定义尺寸：清空。

## 行为边界

- 只改变此功能上线后新建的 `generator` 节点。
- 不覆盖任何已有 API 生成节点的平台、模型、比例、分辨率、质量、补满或数量。
- 不把某个节点的手动修改写入全局默认值。
- 切换平台或模型时，继续使用现有兼容性校验；若所选模型不支持当前选项，由现有归一化逻辑处理。
- 不改变 API 设置页、账号模型获取、Google/Gemini CLI、ModelScope、RunningHub、ComfyUI、RealESRGAN 或其他节点。

## 实现结构

在 `static/js/canvas.js` 中增加可独立测试的 API 节点默认值构造逻辑，并由 `addGeneratorNode()` 调用。平台和模型选择复用现有 provider/model 查询函数，不复制 API 配置数据。

参考图连接后，仅当节点仍处于新建默认比例状态、用户没有主动选择过比例时，才自动改为 `source`。一旦用户手动选择比例，后续输入刷新不覆盖用户选择。

## 兼容与迁移

现有 `applyGeneratorApiDefaults()` 只负责旧数据兼容，不用于覆盖已保存节点的新默认配置。新节点写入新的默认版本标记，以避免加载画布时被旧迁移逻辑再次修改。

## 测试与验收

- 新建 API 节点得到预期平台、模型、2K、1:1、high、补满关闭和数量 1。
- 接入参考图片后，未手动改过比例的新节点使用原图比例。
- 用户手动选择 9:16 等比例后，连接或刷新参考图片不会覆盖该选择。
- 保存并重新加载后，该节点的手动设置保持不变。
- 加载已有画布时，旧 API 节点的原设置不被本次功能覆盖。
- 当 65535 或 gpt-image-2 不可用时，节点能回退到现有可用平台与模型。
- 运行相关前端测试，并执行浏览器检查确认节点显示和保存恢复行为。
